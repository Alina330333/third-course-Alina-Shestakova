# Лабораторная работа 9. Программный 3D-рендерер с Z-буфером

## Запуск
Откройте `index.html` в браузере.

## Что изменилось относительно ЛР8
В ЛР8 рисовался только каркас через `ctx.lineTo()`. Здесь добавлены:
- 12 ориентированных треугольников куба вместо рёбер;
- собственная растеризация через `ImageData` и барицентрические координаты;
- Z-буфер для попиксельного разрешения видимости;
- отсечение по ближней плоскости для треугольников;
- перспективно-корректная интерполяция глубины через `1/z`;
- переключение каркас/закраска и ортографическая/перспективная проекция.

## Геометрия
**Куб:**
- Вершины: от `(-1,-1,-1)` до `(1,1,1)`.
- 6 квадратных граней, каждая разбита на 2 треугольника — итого 12 ориентированных треугольников.
- Порядок индексов задаёт наружную ориентацию.

## Формула барицентрических весов
Для треугольника `A, B, C` и точки `P`:
- `area = edge(A, B, C)`
- `wa = edge(B, C, P) / area`
- `wb = edge(C, A, P) / area`
- `wc = edge(A, B, P) / area`

где `edge(a, b, p) = (b.x - a.x)(p.y - a.y) - (b.y - a.y)(p.x - a.x)`.

Точка внутри треугольника, если `wa, wb, wc >= -eps`.

## Цветовой буфер и Z-буфер
- **Цветовой буфер** — `ImageData` размером `width × height`, RGBA по 4 байта на пиксель. Запись через `pixels[offset]`, вывод одним `ctx.putImageData`.
- **Z-буфер** — `Float64Array(width * height)`, инициализируется `Infinity`. Для каждого пикселя хранится ближайшая принятая глубина. Если новая глубина меньше — цвет перезаписывается, Z обновляется.

## Почему в перспективе интерполируется 1/z
После перспективного деления экранные координаты нелинейно зависят от `z`. Линейная интерполяция `z` по экранным весам даёт неверную глубину 3D-плоскости. Корректно интерполируется обратная глубина:
- `invZ = wa / zA + wb / zB + wc / zC`
- `z = 1 / invZ`

В ортографической проекции `z` интерполируется линейно.

## Ручной расчёт для одного пикселя
Пусть после проекции:
- `A = (40, 30, z=2)`
- `B = (170, 50, z=3)`
- `C = (90, 150, z=4)`

Пиксель `P = (80.5, 60.5)`.
- `edge(A,B,C) = (170-40)(150-30) - (50-30)(90-40) = 15600 - 1000 = 14600`
- `edge(B,C,P) = (90-170)(60.5-50) - (150-50)(80.5-170) = (-80)(10.5) - (100)(-89.5) = -840 + 8950 = 8110`
- `wa = 8110 / 14600 ≈ 0.5555`

Если все веса неотрицательны — пиксель внутри. Глубина в перспективе:
- `invZ = 0.5555/2 + wb/3 + wc/4`
- `z = 1 / invZ`

Сравниваем с `depth[idx]`.

## Проверка двух перекрывающихся граней
В коде цвет чередуется по индексу треугольника (`color1` / `color2`). При вращении куба передние и задние грани перекрываются, но видимая поверхность определяется Z-буфером, а не порядком отрисовки. Если поменять порядок треугольников в массиве `triangles` местами, картинка не изменится — это гарантирует Z-тест.

## Отсечение по ближней плоскости
Если вершина треугольника имеет `z < near` (где `near = 0.1`), полигон отсекается плоскостью `z >= near` по алгоритму Сазерленда–Ходжмена. Точка пересечения ребра `A → B`:
- `t = (near - A.z) / (B.z - A.z)`
- `P = A + t * (B - A)`

После отсечения может получиться 0, 3 или 4 вершины; четырёхугольник триангулируется веером вокруг первой вершины. Отсечение выполняется в координатах камеры до перспективного деления.

## Результаты тестов
- Один треугольник внутри Canvas заполняется: да.
- Вырожденный треугольник не рисуется: да (проверка `area < 1e-12`).
- Выход за края Canvas не ломает буфер: да (clamp в bounding box).
- Два перекрывающихся треугольника не зависят от порядка: да (Z-буфер).
- Ортографическая проекция: ближний закрывает дальний: да.
- Перспективная проекция: `1/z` интерполяция: да.
- Треугольник с вершиной за `near` отсекается: да (`clipPolygonNear`).
- Куб не превращается в прозрачный каркас: да.
- Сброс восстанавливает состояние: да.
- Back-face culling не меняет видимое изображение замкнутого куба: да (опционально включён).
