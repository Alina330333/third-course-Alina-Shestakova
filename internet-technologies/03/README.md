# Лабораторная работа 3. HTTP, Fetch API и работа с JSON

## Файлы
- `index.html` — разметка
- `style.css` — оформление
- `app.js` — состояние, fetch, фильтр, render

## Ответы

**Какой endpoint используется?**
`https://jsonplaceholder.typicode.com/users` — учебный API, отдаёт массив из 10 пользователей в JSON.

**Какой HTTP-метод отправляется?**
`GET`. `fetch(API_URL)` без второго аргумента использует GET по умолчанию.

**Где хранится состояние?**
В объекте `state` в `app.js`: `users`, `isLoading`, `error`, `filter`. HTML ничего не хранит.

**Какие состояния интерфейса предусмотрены?**
1. Данные ещё не загружены.
2. Идёт загрузка.
3. Ошибка.
4. Данные получены.
5. Фильтр (в том числе «никого не найдено»).

**Как обрабатывается ошибка?**
Через `try/catch` вокруг `fetch`. Плюс проверка `response.ok` — если код не 200–299, бросаем ошибку. В `catch` записываем текст в `state.error`. В `finally` снимаем `isLoading`, чтобы интерфейс не завис на «Загрузка...». Пользователь видит сообщение на странице, детали ошибки идут в Console.

**Какие поля участвуют в фильтрации?**
`name`, `username`, `email`. Регистр не учитывается, поиск по подстроке.

**Что видно в Network?**
При успехе — строка `users`, метод GET, статус `200 OK`, тип `application/json`. При неправильном адресе — строка красная, статус `404` или сетевая ошибка.
